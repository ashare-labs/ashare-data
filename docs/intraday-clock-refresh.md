# 秒级来源标签与微秒收讫：严格比较，有限重取

新采集使用 `ad-intraday-observation.v3`。v1/v2 读端解释保持不变。
`session_reference.snapshot()` 的当日及 `source_as_of <= observed_at` 检查没有改变；
没有新增一秒、半秒或其他容差，也没有改写来源时间或本机时钟。

本入口依赖显式配置的本地行动基线，公开包不附原文；位置与缺失行为见[本地证据说明](calendar-pilot-scope.md#本地证据与公开安装包)。下述真实回执仅是本地历史验收记录，公开回归使用自写合成输入。

## 可证事实与未知项

四份 2026-10-15 封存 admission 都返回整数 `date` 与 `time`，后者按 HHMMSS 编码。
10 月 14 日已封存的上交所 `search_HQ_2021.js`（SHA-256
`e2c944248245259c646f54014920795e8dff32b83ddf1d2b6f64dc465c243d96`）
用 `dateFormat(resultData.date + "" + resultData.time)` 展示更新时间，格式函数切分时、分、秒。
这证明字段的编码分辨率，不证明生成端按截断、四舍五入或向上取整。

这是同日的来源/收讫顺序不一致，不是旧日行情。收讫在完整读取 HTTP body 并写入不可变
blob 后记录；微秒序列化不等于微秒级时钟准确性。现有证据不能确定源时钟、本机时钟偏差、
时间标签舍入方式或更新时间是否等于成交/发布时间，也没有可使用的误差上界。

若来源标签 `S` 是整秒、收讫 `R` 精确到微秒，则
`S <= R` 与 `S <= floor(R, 秒)` 等价。因此截断收讫精度不能解决三次失败；
对收讫取上整或假设来源有 ±0.5 秒误差，则额外引入了现有证据没有证明的语义。

## 实际处理

完整采集后，用生产 `assess` 判断原因。只有 blocker 集合恰好为当前限价的时钟错误，且
每项来源诊断均为同日 SSE 标签超前，才重新请求三份 SSE 快照和一份 Sina 报价。
前 110 份资料在同一次有界采集内复用；交易日、公司行动、身份和停牌等准入检查仍全部重算。
执行阶段先独立校验分钟证据，避免报价错误连带产生虚假的“无共同分钟”；价格/限价匹配仍须
上游通过，不能用这个分离跳过限价。

独立成交量检查仅针对按原规则选出的最新共同分钟。该分钟零量与同一证券的报价超前并存时，
保留两个原因并停止报价重取；其他候选或非共同分钟的零量不因此变成新阻断。被选分钟零量时
仍拒绝，不回退到更早的正量分钟；`_bars` 对合法零量 K 线的解析语义不变。

- 默认最多追加两轮（8 次请求）；CLI `--quote-refresh-rounds 0/1/2` 可缩小上限。
- 每轮四项均重新请求；所有原始 body、开始/收讫时间、错误和顺序封存在 `responses`。
  `sources` 必须是各源最后一次响应的严格投影，不能挑选“最有利”的旧回执。
- 新响应仍按它自己的收讫时刻严格检查。即使 body 字节相同，也必须有一次实际的新请求和收讫；
  不能等时钟向前走后替换旧收讫时间。
- 仍使用原来的每次请求前 225 秒预算、最终 240 秒及连续竞价窗口约束；不跨新采集复用材料。
  A宽仍独立校验计划意图/执行截止时间。
- 读端复算每轮触发原因，验证完整顺序、全部 body SHA 和最后响应选择。删除失败响应、用旧日
  输入伪造重试理由或增加未授权轮次都会被拒绝。

`refresh.status` 为 `ready`、`blocked_other_evidence` 或 `retry_limit_reached`；采集中间态
为 `refresh_quotes`。时钟矛盾未消失时 `retryable=true` 但 `assessment.ready=false`，没有成交权限。
请求预算耗尽的 attempt 另标 `budget_exhausted`、`retryable=false`，不把未完成轮次封成可用 packet。
`retryable` 表示值得再观察的来源顺序问题，不是来源时间可信或无限重试授权。包括大于一秒的真正
未来标签在内，任何正超前量都不被容忍；策略只允许重新观察，不定义误差豁免窗口。

第一份的 SSL 停牌源超时和时钟问题并存，因此不做报价局部重取。旧日、部分返回、缺字段、
独立分钟错误、其他已解析的停牌/身份/限价错误也不符合触发条件。此策略不解决所有网络可用性问题。

## 定向验证与限制

A宽的同一 `scripts/replay_sealed_responses.py` 入口保留九份原始采集的单轮回放，另加入两组
`derived_response_schedule`：完整使用真实 02 的 114 份响应，追加真实 03 的四份报价仍阻断；
再追加真实 04 的四份报价后通过。122 次响应对比三次全量采集的 342 次，且经过实际准入和原生账户。
最终持仓、现金、T+1、零新成交与成功封存结果一致。

这些是派生请求选择，**不是当天实际发生的一次采集**。所有保留的请求/收讫时刻、原始字节及间隔
不变；因此不推断立即重试必然返回同样内容，也不声称实盘延时已缩短。若源时钟长期超前、出现其他
错误或用完预算，仍明确阻断；这是一条有界恢复路径，不是源准确性或可用性保证。

`tests/test_intraday_refresh.py` 覆盖真实三个微秒差附近及 ±1 µs、整秒相等、UTC 等价、旧日/未来日、
真实未来秒、采集/执行重取、持续超前耗尽、停牌/坏分钟并发、删除原回执、伪造触发理由及总预算。
普通读端仍拒绝回放证据，所有定向测试和派生调度均不能当真实市场结果。

需要配套认识 v3 的 A宽候选；不能将新采集包投给只认识 v1/v2 的固定运行包。
